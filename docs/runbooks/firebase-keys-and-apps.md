# مفاتيح Firebase وتطبيقاته

مشروع الإشعارات: **`snayah-5f07b`**. هذا الملف لعملين لا يقوم بهما إلا صاحب الحساب من وحدة التحكّم — ولكلٍّ منهما أداةٌ تجعل خطوته آمنة.

---

## ١) تدوير مفتاح حساب الخدمة

**متى:** كلّما اطّلع على المفتاح من لا ينبغي — نسخٌ في محادثة، أو ملفٌ أُرسل، أو جهازٌ فُقد. والمفتاح الحالي **مكشوف** (ظهر في نصّ جلسة عمل بتاريخ ٢٦ أغسطس ٢٠٢٦)، فتدويره مستحقّ.

المفتاح لم يدخل المستودع قطّ — تحقّقتُ من التاريخ كلّه (`git log -S`): لا مادّة مفتاح، ولا معرّفه، ولا ملفٌ متتبَّع تحت `.secrets/`. الكشف كان في نصّ المحادثة وحده.

**الخطر في الترتيب:** من حذف المفتاح القديم قبل أن يتأكّد أن الجديد يعمل أسكت إشعارات المنصّة كلها بلا أن يدري — الخادم يقرأ المفتاح عند الإقلاع ولا يُجرّبه إلا عند أول إشعار، فلا خطأ يظهر.

**فاجعل الترتيب هكذا:**

1. أنشئ مفتاحاً جديداً (ولا تحذف شيئاً بعد):
   `https://console.cloud.google.com/iam-admin/serviceaccounts?project=snayah-5f07b`
   → `firebase-adminsdk-fbsvc@…` → **Keys** → **Add key → Create new key → JSON**

2. ثبّته — والأداة تُثبت أنه يعمل قبل أن تعتمده، وتُعيد القديم إن رفضه Google:

```bash
node apps/api/tools/rotate-fcm-key.mjs
```

3. أعد تشغيل الخادم كي يقرأه:

```bash
./run.sh stop && ./run.sh
```

4. **الآن** احذف المفتاح القديم `1e721c26f044…` من نفس الصفحة، ثم امحُ النسخة الاحتياطية التي طبعت الأداة مسارها (`rm -P …`).

وللسؤال «هل مفتاحي سليم؟» في أي وقت — قبل التدوير أو يوم تصمت الإشعارات:

```bash
node apps/api/tools/rotate-fcm-key.mjs --check
```

يُبادل المفتاح برمز وصولٍ من Google فعلاً، ويفحص رسالةً بـ`validate_only` (تُفحص ولا تُرسَل، فلا يهتزّ جوال أحد).

## ٢) حذف تطبيقات `com.example.*` الستة

سُجّلت بالخطأ عند أول إعداد لـFirebase (معرّف الحزمة الافتراضي قبل تصحيحه إلى `com.issa.*`). لا يبنيها شيء ولا يستخدمها أحد، لكنها تبقى في الحساب تُربك من يقرؤه لاحقاً — والأسماء المعروضة متطابقة، فالفارق في معرّف الحزمة وحده.

احذفها من: `https://console.firebase.google.com/project/snayah-5f07b/settings/general`

| المنصّة | معرّف الحزمة | معرّف التطبيق |
|---|---|---|
| ANDROID | `com.example.sinaaty.customer` | `1:960690022426:android:61d9b3fa0f039bd94149a3` |
| ANDROID | `com.example.sinaaty.partner` | `1:960690022426:android:bddacc89c81c79e14149a3` |
| ANDROID | `com.example.sinaaty.fleet` | `1:960690022426:android:f720344a076b80884149a3` |
| IOS | `com.example.sinaaty.customer` | `1:960690022426:ios:cb4dc53111afd41e4149a3` |
| IOS | `com.example.sinaaty.partner` | `1:960690022426:ios:e6245b5cdbe45c074149a3` |
| IOS | `com.example.sinaaty.fleet` | `1:960690022426:ios:e918042946942e9d4149a3` |

**لا تحذف** الستة العاملة `com.issa.sinaaty.{customer,partner,fleet}` لكل منصّة. وتبقى `com.issa.sinaaty` (أندرويد، بلا لاحقة) مسجّلة ولا يستعملها بناء: كل نكهة تُضيف لاحقتها (`applicationIdSuffix`)، فلا متغيّر بناءٍ يحمل المعرّف المجرّد. حذفها اختياري ولا يضرّ بقاؤها.

**وبعد الحذف** جدّد ملفّات الإعداد لتسقط منها العملاء الثلاثة القدامى (`google-services.json` ما زال يحملهم):

```bash
cd apps/mobile && flutterfire configure --project=snayah-5f07b
```

ثم تحقّق أن القائمة صارت سبعة:

```bash
firebase apps:list --project snayah-5f07b
```

## ما يحرسه الرمز بلا تدخّل

- المفتاح يُقرأ من `apps/api/.secrets/fcm.json` (صلاحيات `600`، والمجلّد مستثنى في `.gitignore`) عبر `tools/with-secrets.sh` — فلا يُكتب سرٌّ في `.env` ولا في المستودع.
- ومفتاحٌ مشوّه لا يطبع مادّته: `JSON.parse` يضع مقطعاً من مُدخَله في نصّ خطئه، فالمُحوِّل يبتلع السبب ويرفع رسالةً نظيفة — يحرسه اختباران في `apps/api/src/modules/notifications/__tests__/fcm.test.ts`.
