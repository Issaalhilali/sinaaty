# عطل تكامل خارجي (نفاذ · نافذ · ZATCA · PSP · منجز)

## الأعراض

- تراكم في `/v1/admin/integrations` (طلبات `failed` أو `dead_letter`).
- شكاوى: «لا يصلني رمز نفاذ»، «الفاتورة لم تُرسل للهيئة»، «دفعت ولم تُقفل الفاتورة».
- تنبيه لوحة Grafana: عمق الـ outbox أو نسبة الفشل.

## أول 5 دقائق

```bash
# ما الذي يتعثّر، ولمن؟
curl -s "$API/v1/admin/integrations?status=failed" -H "authorization: Bearer $TOKEN" | head
curl -s "$API/v1/admin/integrations?status=dead_letter" -H "authorization: Bearer $TOKEN" | head
```

1. **حدّد المزوّد** من `provider` في الصفوف المتعثرة.
2. **حدّد إن كان العطل عندهم أم عندنا**: صفوف `integration_requests` تحمل `error_message` و`attempts`.
   خطأ 401/403 = مشكلة اعتماد عندنا. مهلة/502 = عندهم.
3. **لا تُعطّل التحقق من التوقيع** لتمرير طلب — هذا يفتح باباً دائماً.

## ماذا يحدث تلقائياً (لا تتدخل مبكراً)

- الـ outbox يعيد المحاولة بتراجع أُسّي حتى 6 محاولات، ثم يضع الحدث في `dead_letter`.
- الحجز يتم بـ `FOR UPDATE SKIP LOCKED` بإيجار 120 ثانية، فتعدّد النسخ آمن.
- المهام المجدولة تعمل في نسخة واحدة فقط عبر `job_locks`.

أي أن انقطاعاً لدقائق **يعالج نفسه**. تدخّل فقط عند `dead_letter` أو انقطاع طويل.

## إعادة التشغيل بعد عودة المزوّد

```bash
# إعادة حدث واحد بمفتاح تعادله
curl -X POST "$API/v1/admin/integrations/retry" -H "authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d '{"idempotency_key":"outbox:1234:notifications.wo-created"}'

# أو تفريغ دفعة من الـ outbox يدوياً
curl -X POST "$API/v1/admin/outbox/drain" -H "authorization: Bearer $TOKEN"
```

كل استدعاء خارجي يحمل مفتاح تعادل مخزّناً، لذا **إعادة الإرسال آمنة**: المزوّد لا يفتح ملفاً ثانياً ولا يُصدر سنداً مكرراً.

## حالات خاصة

| المزوّد | الأثر على العميل | ما تقوله للعميل | ملاحظة |
|---|---|---|---|
| **نفاذ** | لا يستطيع الاعتماد | «اعتمد برمز التحقق عبر الجوال» — مسار OTP بديل مبني ويعمل | التوقيع يُخزَّن مع `method=otp` وهو ملزم قانونياً بنفس البصمة |
| **نافذ** | السند لا يصدر | «الأمر معتمد، والسند سيصدر خلال ساعات» | الأمر لا يتوقف؛ الحدث ينتظر في الـ outbox |
| **ZATCA** | الفاتورة صادرة لكن غير مُبلَّغة | لا شيء — الفاتورة صحيحة للعميل | سلسلة ICV/PIH **لا تتقدّم** عند الرفض، فلا تُفسد التسلسل |
| **PSP** | لا يستطيع الدفع | «جرّب مرة أخرى بعد قليل، أو ادفع عند التسليم» | لا تُسجّل دفعة يدوياً؛ الويب هوك هو مصدر الحقيقة |
| **منجز/تقدير** | لا يظهر تقرير الحادث | «سنربط التقرير لاحقاً، والإصلاح يمضي» | لا يوجد مسار حي أصلاً — الوحدة ترفض `live` |

## كيف تتأكد أنك أصلحت

- `/v1/admin/integrations?status=dead_letter` فارغ.
- `/v1/admin/overview` يظهر «صحة التكاملات» خضراء واختلال الدفتر `0.00`.
- عيّنة: افتح سنداً صدر أثناء العطل وتأكد أن حالته `issued` ومرجع نافذ موجود.
