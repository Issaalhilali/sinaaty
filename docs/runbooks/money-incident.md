# حادثة مالية (اختلال دفتر · ضمان معلّق · دفعة مفقودة)

## الأعراض

- `/v1/admin/ledger/health` يعيد اختلالاً ≠ `0.00`.
- عميل دفع ولم تُقفل فاتورته، أو مزوّد لم يصله تحويل.
- مبلغ محتجز في الضمان بعد إغلاق الأمر.

## القاعدة قبل أي شيء

> **لا تُصلح رقماً بيدك.** لا `UPDATE` على `ledger_lines` ولا على `escrow_holds` ولا على الفواتير.
> كل تصحيح = قيد مقابل عبر الـ API. الجداول المالية «إضافة فقط» ومشغّلات القاعدة سترفض التعديل — وهذا مقصود.

## التشخيص (5 دقائق)

```bash
curl -s "$API/v1/admin/ledger/health" -H "authorization: Bearer $TOKEN"     # الاختلال الكلي + القيود غير المتوازنة
curl -s "$API/v1/admin/escrow?status=held" -H "authorization: Bearer $TOKEN" | head
curl -s "$API/v1/admin/payments?status=pending" -H "authorization: Bearer $TOKEN" | head
```

| ما تراه | التفسير الأرجح | الإجراء |
|---|---|---|
| اختلال ≠ 0 | قيد كُتب خارج المسار (لا يحدث عبر الـ API — مشغّل القاعدة يمنعه) | **صعّد فوراً**: أوقف الدفعات، لا تُحرّر شيئاً، افتح تذكرة بأرقام القيود |
| دفعة `pending` والعميل يقول دفع | ويب هوك المزوّد لم يصل | راجع [عطل تكامل خارجي](./integration-outage.md) وأعد إرسال الحدث؛ لا تُنشئ دفعة يدوية |
| ضمان `held` بعد التسليم | مهمة التحرير التلقائي متوقفة أو الحجز مُجمَّد بنزاع | تحقق من `job_locks` والنزاع المرتبط قبل التحرير اليدوي |
| ضمان `frozen` بلا نزاع مفتوح | تجميد قديم لم يُغلق | أغلق النزاع بقرار مكتوب، والتحرير يتبعه |

## الإجراءات المتاحة (كلها تكتب سبباً في سجل التدقيق)

```bash
# تجميد (قابل للتراجع — استخدمه عند الشك)
curl -X POST "$API/v1/admin/escrow/$HOLD/freeze" -H "authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d '{"reason_ar":"شكوى عميل قيد الفحص"}'

# تحرير للمزوّد (غير قابل للتراجع عملياً)
curl -X POST "$API/v1/admin/escrow/$HOLD/release" -H "authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d '{"reason_ar":"تأكيد الاستلام هاتفياً"}'

# استرداد للعميل
curl -X POST "$API/v1/admin/escrow/$HOLD/refund" -H "authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d '{"reason_ar":"تعذّر الإصلاح","amount":"250.00"}'
```

النزاع المالي الحقيقي يُحسم من **غرفة النزاعات** في لوحة الإدارة (تقسيم/استرداد/تحرير) لأنها تكتب القرار والمبالغ
والرسائل في مكان واحد، ثم تنشر القيود المقابلة داخل معاملة واحدة.

## السند والمخالصة

- دفع الفاتورة **يُقفل السند تلقائياً** ويُصدر مخالصة. إن دُفعت الفاتورة والسند ما زال مفتوحاً:
  الحدث `InvoicePaid` عالق في الـ outbox → أعد إرساله؛ لا تُقفل السند يدوياً.
- المخالصة تحمل بصمة محتوى؛ لا تُعاد كتابتها. تصحيح خطأ = مخالصة جديدة تشير للسند.

## كيف تتأكد أنك أصلحت

- الاختلال `0.00` وعدد القيود غير المتوازنة صفر.
- الحجز انتقل من `held/frozen` إلى `released/refunded` وله قيد مقابل في الدفتر.
- سجل التدقيق يحمل سبباً مكتوباً لكل إجراء اتخذته، باسمك.
