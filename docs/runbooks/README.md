# كتيّبات التشغيل (Runbooks)

صفحة واحدة لكل حادثة يُتوقّع أن تقع. كل كتيّب يبدأ بـ **الأعراض**، ثم **ما تفعله الآن**، ثم **كيف تتأكد أنك أصلحت**.
لا يوجد كتيّب هنا لم يُجرَّب فعلياً أو يُذكر صراحةً أنه لم يُجرَّب بعد.

| [عطل تكامل خارجي](./integration-outage.md) | نفاذ/نافذ/ZATCA/PSP لا تستجيب، أو تراكم في الـ outbox |
| [تدقيق مالي عاجل](./money-incident.md) | اختلال في الدفتر، ضمان معلّق، دفعة مفقودة، أو نزاع مالي |

## المبادئ الثابتة

1. **لا تُصلح رقماً بيدك.** أي تصحيح مالي يمرّ عبر قيد مقابل في الدفتر عبر الـ API، لا عبر `UPDATE` على الجداول.
   جداول `audit_log` و`ledger_entries` و`work_order_versions` و`settlements` تمنع التعديل بمشغّلات في قاعدة البيانات —
   **لا تُعطّل المشغّل** (CLAUDE.md §5.2).
2. **كل إجراء حسّاس بسبب مكتوب.** لوحة الإدارة تفرض ذلك، والسبب يُكتب في `audit_log`.
3. **الخصوصية أثناء الحادثة كالخصوصية خارجها.** لا تنسخ أرقام هوية أو IBAN أو أرقام جوال في تذاكر أو محادثات.
4. **إن لم تكن متأكداً، جمّد ولا تُحرّر.** تجميد الضمان (`freeze`) قابل للتراجع؛ تحرير المبلغ للمزوّد ليس كذلك عملياً.
