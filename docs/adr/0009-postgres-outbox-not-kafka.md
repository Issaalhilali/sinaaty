# ADR 0009 — Postgres outbox now; Kafka/RabbitMQ only at defined triggers

- Status: accepted
- Date: 2026-08-20
- Context: Steps 10–20 (integrations, notifications, logistics)

## القرار

نبقى على **outbox في PostgreSQL** (جدول `outbox` + `OutboxProcessor` + `integration_requests`) كناقل للأحداث، ولا نُدخل Kafka
أو RabbitMQ في هذه المرحلة. تُضاف وسيط رسائل فقط عند تحقق أحد المحفزات المذكورة أدناه.

## لماذا

1. **الذرّية هي جوهر المنتج.** كل انتقال حالة يكتب صف التاريخ + سجل التدقيق + حدث الـ outbox **في نفس معاملة قاعدة البيانات**
   (CLAUDE.md §5.2). مع Kafka يصبح النشر خارج المعاملة، فنحتاج outbox على أي حال — أي أن Kafka طبقة *إضافية* لا بديلة.
2. **الحجم.** أحداث الطيار بالآلاف يومياً؛ `FOR UPDATE SKIP LOCKED` على Postgres يخدم عشرات آلاف الأحداث في الدقيقة على
   جهاز واحد — أي أضعاف ما نحتاجه، دون عنصر تشغيلي جديد (ZooKeeper/KRaft، مراقبة، ترقيات، تدريب الفريق).
3. **قابلية التتبّع.** المشرف يرى الحدث المتعثر ويعيد تشغيله من لوحة الإدارة بجملة SQL واحدة (`/v1/admin/outbox/drain|retry`).
4. **مستهلك واحد.** اليوم كل حدث يستهلكه هذا التطبيق نفسه (إشعارات، سندات، فواتير). البثّ لمستهلكين مستقلين — وهو ما يبرّر
   Kafka — لم يظهر بعد.

## محفزات إعادة النظر (أيّها تحقق ⇒ نكتب ADR جديداً ونُدخل الوسيط)

| المحفز | الحد | الوسيط المرجّح |
|---|---|---|
| حجم تتبّع الشاحنات/السطحات (`transport_tracking`) | > 500 رسالة/ثانية مستدامة | Kafka (احتفاظ + إعادة تشغيل) |
| ظهور مستهلك ثانٍ مستقل (تحليلات، بحيرة بيانات، شريك خارجي) | أول مستهلك خارج الـ API | Kafka |
| فصل خدمة عن المونوليث (§ADR 0001) | أول خدمة منفصلة | Kafka |
| تراكم outbox المستمر رغم التوسّع الأفقي | backlog > 10k لأكثر من 5 دقائق بشكل متكرر | RabbitMQ إن كانت المشكلة توزيع مهام لا بثّ |

حتى ذلك الحين تظل قاعدة CLAUDE.md §5.2 سارية: **لا نشر خارج المعاملة، ولا مسار جانبي يتجاوز الـ outbox.**

## النتائج

- `OutboxProcessor` صار يحجز الصفوف ذرّياً (`locked_until` + `FOR UPDATE SKIP LOCKED` + إيجار 120 ثانية) فيصحّ تشغيل عدة نسخ
  من الـ API معاً — وهي القدرة التي كان يُراد Kafka من أجلها.
- المهام المجدولة (تحرير الضمان، الدفعات، مهام القطع) تمرّ عبر `LeaderLock` (جدول `job_locks`) فتعمل في نسخة واحدة فقط.
- إن أُدخل Kafka لاحقاً فمكانه **بعد** الـ outbox: `OutboxProcessor` ينشر إلى الوسيط بدل استدعاء المعالج مباشرة، دون أي تغيير
  في وحدات النطاق.
