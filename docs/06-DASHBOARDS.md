## A. لوحة المشرف (Admin Back-office)

### A.1 الأدوار (`users.platform_role`)
| الدور | الصلاحيات |
|---|---|
| `support` | قراءة كل شيء تقريباً، الرد على التذاكر، إعادة إرسال إشعار، **لا** قرارات مالية |
| `ops` | KYB، النزاعات (وساطة)، تعليق منشأة، إعادة محاولة تكامل، إدارة المناطق الصناعية |
| `finance` | التسويات، Payouts، الاسترجاعات، الـ Ledger، تعديل عمولات منشأة، تقارير مالية |
| `compliance` | ZATCA، السندات/التنفيذ، سجل التدقيق، طلبات حذف البيانات (PDPL)، تصدير الأدلة |
| `super_admin` | كل ما سبق + الإعدادات العامة + إدارة أدوار الفريق |
> كل إجراء حساس (تعليق، استرجاع، قرار نزاع، تعديل عمولة) يتطلب **سبباً نصياً** ويُكتب في `audit_log`. الإجراءات المالية فوق حد معيّن تحتاج **موافقة ثانية** (Maker/Checker).

| إيراد المنصة | `platform_revenue:*` من الـ Ledger | ledger_lines |

| صحة التكاملات | نسبة النجاح آخر ساعة لكل مزوّد + عمق DLQ | integration_requests |

### A.4 الشاشات الحرجة بالتفصيل

**KYB Queue (`/kyb`)**
- طابور مرتب بالأقدم؛ بطاقة المنشأة: النوع، السجل التجاري (صورة + رقم — تحقق يدوي/API لاحقاً)، الرقم الضريبي، IBAN (آخر 4)، الموقع على الخريطة، أعضاء الفريق.
- إجراءات: اعتماد / رفض بسبب (يظهر للمنشأة) / طلب وثيقة إضافية. عند الاعتماد: `organizations.status=active` + إشعار + حد تعرّض مالي أولي (`max_open_exposure_sar`).

**ملف المنشأة (`/orgs/:id`)**
- تبويبات: نظرة عامة (تقييم، أوامر، GMV، نزاعات، نسبة الالتزام)، الأعضاء، المواقع، الوثائق، الاشتراك والعمولة (تعديل بسبب)، المحفظة والتحويلات، السندات، الحسابات الآجلة (للوكلاء/الورش)، سجل التدقيق.
- إجراءات: تعليق/تفعيل، تغيير الباقة، رفع/خفض حد التعرّض، شارة "معتمد".

**مراقبة التكاملات (`/integrations`)**
- لكل مزوّد: مخطط النجاح/الفشل/زمن الاستجابة (24 س)، آخر 100 طلب (`integration_requests`) بحالتها والحمولة **بعد الإخفاء**، DLQ مع زر **إعادة محاولة** (فردي/جماعي) وزر "تعليم كمعالج يدوياً" بسبب.
- Webhooks: الواردة غير المعالجة، توقيع غير صالح، إعادة معالجة.
- شاشة خاصة "**السندات المعلّقة**": كل سند يجب أن يكون مغلقاً (فاتورته مدفوعة) ولم يُغلق — لأن هذا وعد المنتج الأساسي.

**غرفة النزاع (`/disputes/:id`)**
- عمود يسار: الخط الزمني للأمر/الطلب (حالات، توقيعات، نسخ معتمدة مع hash).
- عمود وسط: الأدلة (صور الاستلام/التسليم/قبل/بعد، فيديو القطعة، QR، إثبات التوصيل) قابلة للمقارنة جنباً إلى جنب.
- عمود يمين: الرسائل مع الطرفين، ملاحظات داخلية، **القرار**: إفراج كامل / استرجاع كامل / تقسيم (مبلغ) / استبدال قطعة، مع سبب ⇒ ينفّذ قيود Ledger ويحدّث Escrow ويُغلق ويُخطر.

**المالية (`/payments`, `/escrow`, `/payouts`, `/ledger`)**
- Escrow: قائمة بحالة/تاريخ الإفراج المتوقع؛ تجميد/فك تجميد بسبب.
- Payouts: دفعات اليوم، فاشلة (IBAN خاطئ) مع إعادة، تصدير ملف البنك.
- Ledger: تصفح القيود، ميزان المراجعة (`ledger_balances`)، تسوية مع كشف مزود الدفع (Reconciliation) بفروقات مُبرزة.
- الاسترجاع اليدوي يتطلب موافقة ثانية.

**السندات والتنفيذ (`/notes`, `/enforcement`)**
- السندات حسب الحالة والعمر؛ المتعثرة (> due) مع سجل التذكيرات؛ زر "**تجهيز حزمة التنفيذ**" (يولّد ZIP: السند + الفاتورة + النسخة الموقعة + التوقيعات + صور الفحص) وتتبع حالة الحالة في ناجز يدوياً.

**الإعدادات (`/settings`)**
- محرر `platform_settings` بمفاتيح مسمّاة (مهلة الإفراج، أيام الإشعار للمهجورة، دقائق المزاد، الرسوم…) بتحقق من النوع وسجل تغييرات.
- الباقات والعمولات، فئات الخدمات/القطع/الماركات، المناطق الصناعية (رسم مضلع على الخريطة)، قوالب الإشعارات، فريق المنصة وأدواره.

### A.5 متطلبات تقنية للوحة المشرف
- Next.js 15 (App Router) + TanStack Table (تصفية/فرز/تصفح خادمي) + TanStack Query + shadcn/ui + Recharts.
- مصادقة: نفس API (`platform_role`)، جلسات قصيرة، **2FA إلزامي** لفريق المنصة، IP allowlist اختياري.
- كل صفحة قائمة تدعم: بحث، فلاتر محفوظة، تصدير CSV، روابط عميقة.
- عرض PII مقنّع افتراضياً (هوية/IBAN) مع "إظهار" مسجّل في التدقيق.
- RTL كامل، عربي افتراضي، أرقام غربية للمبالغ.
- Playwright smoke: تسجيل دخول ⇒ KYB approve ⇒ إعادة محاولة تكامل ⇒ قرار نزاع.

## B. لوحة الورشة (داخل Partner App)

### B.1 الشاشة الرئيسية "لوحة اليوم"
| البطاقة | المحتوى | الإجراء بنقرة |
|---|---|---|
| السيارات في الورشة | عدّاد لكل حالة (مستلمة/بانتظار اعتماد/قطع/جاري/جاهزة) | فتح القائمة المفلترة |
| بانتظار العميل | أوامر بانتظار اعتماد > 2 ساعة، سيارات جاهزة > 24 ساعة | تذكير العميل |
| القطع | طلبات آجلة اليوم، طلبات متأخرة عن ETA، عروض مزاد وصلت | فتح الطلب |
| المال | محتجز (Escrow) / متاح / يُحوَّل غداً / مستحق عليّ للوكلاء | المحفظة |
| السندات | مفتوحة (عدد/قيمة)، مستحقة هذا الأسبوع، متعثرة | قائمة السندات |
| الفريق | أوامر لكل فني اليوم | إسناد |
| التقييم | آخر تقييمات + المتوسط | الردود |

### B.2 شاشات فرعية للمدير/المحاسب
- **المحفظة:** الرصيد المحتجز مع تاريخ الإفراج المتوقع لكل أمر، المتاح، التحويلات (`payouts`)، كشف حساب قابل للتصدير، الرسوم المدفوعة.
- **الفواتير والسندات:** فلترة (مدفوعة/آجلة/متعثرة)، لكل سند: القيمة، المتبقي، الاستحقاق، التذكيرات المُرسلة، زر "تحويل للتنفيذ" بعد المهلة.
- **حساباتي الآجلة عند الوكلاء:** لكل وكيل: الحد، المستخدم، المستحق، تواريخ الاستحقاق، سداد.
- **التقارير البسيطة:** الإيراد الشهري، متوسط قيمة الأمر، أعلى الخدمات، زمن الإنجاز، نسبة الاعتماد من أول مرة.
- **الإعدادات:** قائمة أسعار الورشة (خدمات + ساعة عمل)، شروط العقد (رسوم إيواء، مهلة المهجورة)، الفريق والصلاحيات، ساعات العمل، التخصصات.

### B.3 مبدأ
كل بطاقة = سؤال يسأله صاحب الورشة صباحاً: "كم سيارة عندي؟ من ينتظرني؟ أين فلوسي؟ من متأخر عليّ؟" — لا مخططات معقدة على الجوال؛ المخططات في نسخة الويب فقط.

## C. لوحة وكيل القطع (Partner App — ويب أساساً) ولوحة التشليح (جوال)

### C.1 وكيل القطع — الشاشة الرئيسية
| البطاقة | المحتوى |
|---|---|
| الطلبات | جديدة / للتجهيز / مع المندوب / مسلّمة اليوم / مرتجعات |
| الحسابات الآجلة | طلبات جديدة، إجمالي الحدود، المستخدم، **أعمار الديون** (0–30/31–60/60+)، سندات مصدرة/مغلقة |
| المخزون | آخر مزامنة (وقت/نتيجة)، أصناف نفدت وعليها طلب، أصناف بطيئة |
| المزادات | طلبات عروض قريبة الآن، عروضي المقبولة/المرفوضة (السبب: سعر/توفر/وقت) |
| المصادقة | أرقام تسلسلية أُصدرت/رُكّبت هذا الأسبوع، **تنبيهات تقليد** |
| التحصيل | مستحق اليوم/الأسبوع، متأخر، تحويلات المنصة لي |
| التحليلات (Enterprise) | الأكثر طلباً حسب موديل/حي، الطلبات المفقودة، معدل التحويل، حصتي مقابل التجاري/التشليح |

### C.2 شاشات فرعية للوكيل
- **الكتالوج والمخزون:** بحث برقم القطعة/الاسم/OEM، رفع Excel/CSV مع معاينة الأخطاء صفاً صفاً، سجل المزامنة (`inventory_sync_runs`)، تعديل الأسعار (تجزئة/ورش) وقواعد خصم لكل ورشة.
- **الحسابات الآجلة:** لكل ورشة بطاقة ثقة (مدة على المنصة، عدد الأوامر، النزاعات، التقييم، سندات سابقة وسدادها) ⇒ اعتماد/حد/مدة؛ سجل الحركات؛ إرسال تذكير؛ تحويل للتنفيذ.
- **الفروع والمناديب:** مخزون لكل فرع، تعيين مندوب لطلب، تتبع.
- **المصادقة:** إنشاء دفعة أرقام تسلسلية لصنف (توليد QR للطباعة PDF)، خريطة عمليات المسح، بلاغ تقليد.
- **الفريق:** الأدوار (مبيعات/مستودع/محاسبة/بيانات).

### C.3 التشليح — لوحة جوال بسيطة
- بطاقات: **طلبات قريبة الآن** (عدد + أقرب واحد)، عروضي المعلّقة، مبيعات هذا الأسبوع، **الرصيد**، ضماناتي النشطة/مطالبة مفتوحة، تقييمي.
- كل شيء آخر داخل 3 تبويبات فقط: طلبات / مبيعاتي / محفظتي.

## D. بوابة الأسطول (Fleet Portal — Flutter Web) — المرحلة 5
- **نظرة عامة:** المركبات (نشطة/في الورشة/متوقفة)، أوامر بانتظار اعتمادي، الإنفاق هذا الشهر مقابل الميزانية، أعلى 10 مركبات تكلفة.
- **الاعتمادات:** طابور حسب `fleet_policies` (تلقائي تحت حد، اعتماد ثنائي فوق حد)، اعتماد بنقرة أو رفض بسبب، توقيع نفاذ للمعتمِد.
- **المركبات:** استيراد Excel، جواز كل مركبة، جدول صيانة دورية وتنبيهات.
- **الورش المعتمدة:** قائمة الشبكة، الأداء (زمن/سعر/جودة)، إضافة/إزالة.
- **المالية:** الكشف الشهري الموحد (`fleet_statements`)، الفواتير، السندات باسم الشركة، تصدير للنظام المحاسبي (CSV/Excel، لاحقاً API).
- **التقارير:** التكلفة لكل مركبة/فرع/نوع خدمة/شهر، مقارنة بالأسطول المماثل (بعد تراكم البيانات).

## E. مبادئ مشتركة لكل اللوحات
1. **كل رقم قابل للنقر** ويؤدي إلى القائمة التي تفسّره.
2. **الوقت بتوقيت الرياض**، والمبالغ بريالين عشريين وأرقام غربية.
3. **الحالة الفارغة تُعلّم**: لوحة ورشة جديدة تُظهر "أنشئ أول أمر عمل" لا صفراً صامتاً.
4. **الأداء:** بطاقات اللوحات تُقرأ من جداول ملخّصة/Materialized views تُحدَّث كل دقيقة، لا استعلامات ثقيلة عند كل فتح.
5. **الصلاحيات في الخادم**: الواجهة تُخفي، والـ API يمنع.
6. **RTL أولاً**، ثم دعم LTR للإنجليزية.
