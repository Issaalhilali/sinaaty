## 0. مبادئ التصميم الميدانية (لأن المستخدم داخل ورشة، لا في مكتب)

| المبدأ | التطبيق العملي |
|---|---|
| **إبهام واحد، يد متسخة** | أزرار كبيرة (≥ 56dp)، تباين عالٍ، لا قوائم مخفية؛ العمليات الأساسية بنقرتين |
| **الكاميرا أولاً** | كل شيء يبدأ بصورة: صورة اللوحة/الاستمارة ⇒ VIN، صورة القطعة ⇒ عرض، صورة الضرر ⇒ بند |
| **الصوت بدل الكتابة** | الفني يملي البنود صوتياً؛ التحويل لبنود قابلة للتعديل |
| **يعمل بلا إنترنت** | تحديث الحالة والصور تُخزَّن محلياً وتُزامَن؛ ما لا يعمل offline يُخفى بوضوح |
| **العميل لا يحتاج التطبيق ليبدأ** | أول تفاعل عبر رابط SMS/واتساب ⇒ صفحة ويب خفيفة للاعتماد بنفاذ؛ التطبيق يُقترح بعدها |
| **العربية والأرقام** | أرقام عربية غربية (1234) في المبالغ والـ VIN، هجري اختياري بجانب الميلادي |
| **الثقة مرئية** | شارات: "موقّع بنفاذ"، "مضمون بسند"، "قطعة أصلية موثّقة"، "ورشة معتمدة" تظهر في كل مكان مناسب |

## 1. الورشة (Partner App — دور `workshop`)

### 1.1 الأدوار داخل الورشة
| الدور | ما يراه/يفعله |
|---|---|
| **المالك/المدير** | كل شيء + المحفظة + الحسابات الآجلة + اعتماد الأسعار |
| **الفني** | أوامر العمل المسندة له، الفحص المصوّر، تحديث المراحل، إملاء البنود، مسح QR القطع؛ **لا يرى الأسعار الكلية أو المحفظة** |
| **المحاسب** | الفواتير، المدفوعات، السندات، أعمار الديون، التسويات |
| **الاستقبال** | إنشاء أمر العمل، فحص الاستلام، التواصل مع العميل |

### 1.2 يوم في حياة ورشة (Happy path)
```
07:30  المدير يفتح التطبيق: لوحة اليوم — [3 سيارات جاهزة للتسليم] [2 بانتظار اعتماد العميل] [1 قطع متأخرة] [مستحقات محتجزة: 4,300 ر.س]
08:10  عميل يصل ➔ الاستقبال: "أمر عمل جديد" ➔ يصوّر لوحة السيارة ➔ VIN يُقرأ ➔ بيانات السيارة تظهر ➔ يدخل جوال العميل
       ➔ فحص الاستلام: 8 زوايا مُرشدة (Overlay على الكاميرا) + عداد + وقود + الأضرار السابقة (ينقر على مخطط السيارة) ➔ العميل يوقّع الاستلام (OTP)
08:40  الفني يفحص ➔ يملي صوتياً: "تغيير طقم دسكات أمامي، فلتر زيت، وزيت خمس لتر" ➔ البنود تظهر ➔ يعدّل الأسعار من قائمة أسعار الورشة
       ➔ يحتاج قطعة: "دسكات أمامي" ➔ يبحث بالـ VIN ➔ [وكيل: أصلي 420 متوفر — 3 س] [تجاري 260] [تشليح: اطلب عروضاً] ➔ يختار الوكيل بالآجل ➔ تُضاف للأمر
09:00  المدير يراجع ➔ "طلب اعتماد العميل" ➔ SMS/واتساب للعميل برابط
09:12  إشعار: "العميل اعتمد بنفاذ ✅ — سند لأمر أُصدر (آجل)" ➔ الحالة تلقائياً: بانتظار القطع
11:30  مندوب الوكيل يسلّم ➔ الفني يمسح QR القطعة ➔ "أصلية ✅ — ربطها بأمر العمل #WO-2026-000123؟" ➔ نعم ➔ الحالة: جاري العمل
13:00  الفني يصوّر "قبل/بعد" لكل بند ➔ ينقر "جاهزة" ➔ العميل يستلم إشعاراً بالصور
15:00  العميل يصل ➔ فحص التسليم (4 زوايا سريعة) ➔ الفاتورة تُصدر بنقرة (ZATCA QR) ➔ العميل يدفع بجواله (Mada) أو نقداً (يُسجَّل)
       ➔ إن دفع كاملاً: السند يُغلق تلقائياً + مخالصة ➔ التوقيع على الاستلام (نفاذ/OTP)
15:05  الإشعار للمدير: "تم الاستلام — المبلغ في الحساب الضامن، يُحوَّل خلال 72 ساعة أو عند تأكيد العميل"
```

### 1.3 خريطة شاشات الورشة
```
[لوحة اليوم] ─ [أوامر العمل: مستلمة | بانتظار اعتماد | قطع | جاري | جاهزة | مسلّمة]
              ─ [أمر عمل: بنود | صور | حالة | فاتورة | سند | محادثة العميل]
              ─ [قطع الغيار: بحث VIN | سلة | طلباتي | حسابي الآجل عند الوكلاء | طلبات عروض (مزاد)]
              ─ [المحفظة: محتجز | متاح | تحويلات | فواتير | سندات (مفتوحة/مغلقة) | متعثرون]
              ─ [العملاء والسيارات] ─ [الفريق والصلاحيات] ─ [الإعدادات: قائمة الأسعار، ساعات العمل، شروط العقد]
```

### 1.4 حالات حدّية ومعالجتها
| الحالة | المعالجة |
|---|---|
| العميل بلا جوال ذكي / لا يريد التطبيق | رابط ويب خفيف للاعتماد بنفاذ؛ وإن تعذّر: اعتماد ورقي مصوّر + OTP على جوال أي رقم يملكه (يُعلَّم "توثيق مخفّض" ولا يُصدر سند) |
| العميل غير مسجّل بنفاذ (مقيم بلا حساب/شركة) | OTP + صورة الهوية؛ للسندات يلزم نفاذ — يُشرح للورشة أن الحماية أقل |
| زيادة نطاق العمل بعد البدء | "تعديل الأمر" ⇒ نسخة جديدة ⇒ اعتماد جديد؛ لا يمكن إصدار فاتورة تفوق آخر نسخة معتمدة |
| انقطاع الإنترنت داخل الورشة | تحديث الحالة/الصور/الإملاء تعمل offline وتُزامَن؛ الاعتماد بنفاذ والدفع تظهر "يتطلب اتصالاً" |
| السيارة جاهزة والعميل لا يرد 15 يوماً | تذكيرات تلقائية ⇒ إشعار رسمي ⇒ عدّاد رسوم إيواء (إن كانت في العقد) ⇒ زر "بدء إجراءات المركبة المهجورة" |
| عميل يرفض الدفع عند الاستلام | السيارة تبقى؛ السند قائم؛ زر "تحويل للتنفيذ" بعد المهلة؛ المنصة تُجهّز الملف |
| خلاف على القطعة المركّبة | كل قطعة لها QR/صورة/رقم تسلسلي في أمر العمل ⇒ الدليل جاهز للنزاع |
| نقد فعلي بدل الدفع الإلكتروني | يُسجَّل "دفع نقدي مؤكّد من الطرفين" (OTP للعميل) ⇒ يُغلق السند؛ لا يمر بـ Escrow ولا عمولة (رسم ثابت فقط) |

## 2. العميل (Customer App + رابط ويب خفيف)

### 2.1 أول لقاء (بدون تثبيت التطبيق)
```
SMS/واتساب: "ورشة النور أنشأت أمر إصلاح لسيارتك كامري 2019 بقيمة 1,265 ر.س. راجعه واعتمده: sinaaty.sa/a/xk9…"
➔ صفحة ويب: البنود + الصور + السعر + شروط الدفع (فوري/آجل 30 يوم) + "ماذا يعني توقيعك؟" (سطران)
➔ زر "اعتماد عبر نفاذ" ➔ تطبيق نفاذ يطلب الرقم ➔ رجوع للصفحة: "تم ✅ — حمّل التطبيق لتتابع سيارتك بالصور"
```

### 2.2 داخل التطبيق
```
[سياراتي] ─ [سيارة: جواز السيارة (Timeline) | أوامر عمل | ضمانات | استدعاءات]
[أمر العمل الحالي] ─ خط زمني حي بالصور: استلمناها ➔ فحص ➔ بانتظار قطع (وكيل X — أصلي) ➔ جاري العمل ➔ جاهزة
                   ─ [اعتماد/تعديل] [الفاتورة + ادفع] [السند: قيمة، استحقاق، حالة] [المخالصة PDF] [افتح نزاعاً]
[اطلب] ─ ورشة قريبة (بحث بالتخصص/الماركة/التقييم الموثّق) | قطعة (VIN — عروض خلال دقائق) | سطحة الآن
[محفظتي] ─ ضمانات (QR لكل قطعة) | فواتير | سندات | مخالصات
[الإشعارات] [حسابي]
```

### 2.3 لحظات مهمة
- **قبل الاعتماد:** يرى مقارنة "متوسط سعر السوق لهذه الخدمة" (بعد تراكم البيانات) ⇒ طمأنينة.
- **بعد الجاهزية:** إشعار بصور قبل/بعد + زر "أؤكد الاستلام" (يفرج عن الأموال فوراً) أو "لديّ ملاحظة" (يفتح نزاعاً ويجمّد).
- **عند البيع:** "شارك جواز السيارة" ⇒ رابط عام بلا بيانات شخصية.

### 2.4 حالات حدّية
| الحالة | المعالجة |
|---|---|
| لم يستلم SMS | الورشة تُظهر QR على شاشتها ليمسحه العميل |
| يريد دفعاً جزئياً | مسموح؛ السند يبقى بالمتبقي؛ المخالصة عند الصفر |
| يخشى السند | شرح: "السند يُغلق تلقائياً فور دفعك — ولا يمكن للورشة زيادة المبلغ دون توقيعك" |
| العميل شركة (أسطول) | الاعتماد يذهب لمعتمد الأسطول حسب السياسة؛ سند باسم الشركة |

## 3. وكيل / موزّع قطع الغيار (Partner App دور `parts_distributor` + لوحة ويب)

### 3.1 الأدوار
| الدور | ما يفعله |
|---|---|
| **مدير المبيعات** | يعتمد الحسابات الآجلة والحدود، يراقب أعمار الديون، يرى تحليلات الطلب |
| **موظف المستودع/الفرع** | يستقبل الطلبات، يجهّز، يطبع/يلصق QR، يسلّم للمندوب |
| **المحاسب** | الفواتير، السندات، التحصيل، التسويات |
| **مسؤول البيانات (اختياري)** | رفع الكتالوج/التوافق/المخزون، ربط ERP |

### 3.2 التهيئة (مرة واحدة — بمساعدة فريقنا الميداني)
```
1. تسجيل المنشأة + KYB (سجل تجاري، ضريبي، IBAN)
2. رفع الكتالوج: Excel بأعمدة (رقم القطعة، العلامة، الاسم، أرقام OEM، الفئة) ➔ معاينة الأخطاء ➔ اعتماد
3. رفع التوافق: Excel (رقم القطعة، الماركة، الموديل، السنوات) أو "استخدم بيانات التوافق المشتركة" للأرقام المعروفة
4. المخزون: CSV يومي مجدول من الـ ERP (SKU، الكمية، سعر التجزئة، سعر الورش) أو API — تقرير مزامنة بعد كل تشغيل
5. سياسة الآجل: الحد الافتراضي للورش الجديدة، المدة، الخصم، "يلزم سند" (نعم افتراضياً)
6. المندوبون/التوصيل: مناديب الوكيل أو شبكة المنصة
```

### 3.3 يوم في حياة الوكيل
```
08:00  لوحة الفرع: [طلبات جديدة: 14] [للتجهيز: 6] [مع المندوب: 4] [حسابات آجلة بانتظار الاعتماد: 2] [مستحق اليوم: 18,400 ر.س]
08:05  طلب Buy Now من ورشة النور (آجل، حد متاح 12,000): دسكات + فلتر ➔ "تجهيز" ➔ يطبع ملصق QR للوحدة (إن كانت مسلسلة) ➔ "تسليم للمندوب"
       ➔ في الخلفية: سند لأمر أُصدر باسم الورشة تلقائياً — يظهر رقم السند في الطلب
09:30  طلب حساب آجل جديد من ورشة "السرعة": المنصة تعرض ملفها (منذ 4 أشهر، 62 أمر عمل، صفر نزاعات، تقييم 4.7) ➔ يعتمد بحد 8,000
10:00  طلب مزاد عكسي وصل (فلتر هواء لكزس 2017 — 3 كم منه): "قدّم عرضاً" ➔ السعر يُقترح من مخزونه ➔ إرسال بنقرة
13:00  تنبيه: "الرقم التسلسلي BX-4471 مُسح في جدة وفي الرياض خلال ساعتين — احتمال تقليد" ➔ فتح بلاغ
16:00  تقرير: "12 طلباً في منطقتك لقطعة (رديتر كامري 2015) خلال أسبوع — لديك صفر مخزون؛ ذهبت للتشليح" ➔ قرار شراء
نهاية الشهر: أعمار الديون: مستحق 30+ يوم: 3 ورش ➔ التذكيرات تلقائية ➔ زر "تحويل للتنفيذ" للمتعثر
```

### 3.4 خريطة الشاشات
```
[لوحة الفرع] ─ [الطلبات: جديدة | تجهيز | توصيل | مسلّمة | مرتجعات]
             ─ [الكتالوج والمخزون: بحث | رفع ملف | سجل المزامنة | القطع منخفضة المخزون]
             ─ [الحسابات الآجلة: طلبات | نشطة (حد/مستخدم/متأخر) | أعمار الديون | سندات]
             ─ [المزادات: طلبات عروض قريبة | عروضي]
             ─ [المصادقة: دفعات الأرقام التسلسلية | تنبيهات التقليد]
             ─ [التحليلات: الطلب حسب موديل/حي | الطلبات المفقودة | معدل التحويل]
             ─ [المحفظة والتحصيل] ─ [الفريق والفروع]
```

### 3.5 حالات حدّية
| الحالة | المعالجة |
|---|---|
| المخزون في ERP غير دقيق ⇒ بيع قطعة غير متوفرة | حجز الكمية عند الطلب؛ إن لم تتوفر عند التجهيز: إلغاء بنقرة مع بديل مقترح؛ يُخصم من "معدل الالتزام" |
| الورشة تجاوزت الحد الائتماني | الطلب يُرفض آجلاً ويُعرض "ادفع فوراً" أو "اطلب رفع الحد" |
| قطعة وصلت خطأ/تالفة | الورشة تصوّر عند الاستلام ⇒ مرتجع ⇒ السند يُعدَّل/يُلغى؛ إن رُكّبت: تُعالج كمطالبة ضمان ثلاثية |
| الوكيل بلا فريق تقني للـ ERP | CSV يدوي يومي (5 دقائق) + فريقنا يساعد؛ التوافق من البيانات المشتركة |
| رقم القطعة غير موجود في الكتالوج المشترك | يُنشأ من ملف الوكيل ويُصبح جزءاً من الكتالوج العام (بموافقته) |

## 4. التشليح (Partner App دور `scrapyard`) — الأبسط عمداً

### 4.1 يوم في حياة التشليح
```
09:00  إشعار: "طلب قطعة قريب منك: قير أوتوماتيك كامري 2016–2018 — 4 كم — ينتهي خلال 55 دقيقة"
09:03  يفتح الطلب: VIN + صور + ملاحظات ➔ "قدّم عرضاً": يصوّر القطعة (فيديو 15 ثانية) + السعر + الضمان (7/14/30 يوم) + رقم هيكل السيارة المصدر (اختياري) ➔ إرسال
09:40  إشعار: "تم قبول عرضك ✅ — المبلغ محجوز في الحساب الضامن — جهّز القطعة للمندوب/السطحة"
10:30  المندوب يستلم (OTP) ➔ الورشة تستلم وتركّب ➔ بعد التأكيد أو 72 ساعة: "تم تحويل 1,800 ر.س لمحفظتك"
      ➔ شهادة ضمان رقمية صدرت للعميل تلقائياً باسم التشليح
```
### 4.2 شاشات التشليح
```
[طلبات قريبة (خريطة/قائمة)] ─ [عروضي: بانتظار | مقبولة | مرفوضة]
[مبيعاتي] ─ [ضماناتي: نشطة | مطالبات] ─ [مخزوني (اختياري: سيارات مفكّكة + قطع)] ─ [المحفظة]
```
### 4.3 حالات حدّية
| الحالة | المعالجة |
|---|---|
| لا يجيد الكتابة | العرض = فيديو + سعر فقط؛ الملاحظات صوتية |
| القطعة تعطّلت داخل الضمان | مطالبة عبر التطبيق ⇒ التشليح يختار (استبدال/استرجاع) خلال 48 ساعة وإلا تُحوَّل لوساطة؛ المبلغ من محفظته |
| قطعة "مسروقة"؟ | رقم هيكل السيارة المصدر يُسجَّل؛ يمكن مقارنته لاحقاً؛ التشليح المخالف يُوقف |
| كثرة الإشعارات | فلاتر: الماركات التي يفكّكها فقط + نطاق كم |

## 5. السطحة / المندوب (دور `driver`)
```
[متاح/غير متاح] ➔ [مهمة قريبة: من/إلى، نوع (سطحة/توصيل قطعة)، السعر] ➔ قبول ➔ ملاحة ➔ صورة عند الاستلام ➔ ملاحة ➔ صورة + OTP المستلم ➔ "تم" ➔ الأرباح
```
- السطحة تُطلب من داخل أمر العمل (العميل أو الورشة) أو مستقلة.
- توصيل القطع يُدمج تلقائياً مع طلبات الوكيل/التشليح.

## 6. المشرف (Admin) — ما يحتاجه ليدير السوق يومياً
- طابور KYB (ورش/وكلاء/تشاليح) مع الوثائق والقرار.
- مراقبة التكاملات: كل سند لم يُصدر/يُغلق، كل فاتورة ZATCA مرفوضة، كل Webhook فاشل — بزر إعادة محاولة.
- النزاعات: الأدلة (صور، توقيعات، QR) في شاشة واحدة ⇒ قرار (إفراج/استرجاع/تقسيم).
- التحصيل: السندات المتعثرة، حزم التنفيذ الجاهزة.
- الإعدادات: العمولات، الرسوم، مهلة الإفراج، الباقات، المناطق الصناعية.
