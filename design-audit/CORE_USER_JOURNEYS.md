# الرحلات الأساسية — كما هي اليوم، وما يعوقها

> كل رحلة: نقطة البداية → النيّة → الخطوات الفعلية (عدّت على الجهاز أو في الكود) → ما يُقاس → الاحتكاك المرصود.

## J1 — عميل: «سيارتي معطّلة» ⟵ ورشة تقبل
- البداية: الرئيسية (تبويب «الرئيسية») → بطاقة «قل وش فيها» (مساعد محلي) أو «إصلاح» من شبكة الخدمات.
- الخطوات اليوم: وصف (نص/صوت) → سيارة → موقع → نطاق → إرسال → شاشة الطلب (قائمة/خريطة عروض) → قبول عرض → أمر عمل.
- **الاحتكاك المرصود**: بابان لنفس الفعل على الشاشة نفسها (بطاقة المساعد + شبكة «إصلاح»)؛ شبكة الخدمات الست ببطاقات متطابقة تنافس البطاقة الرئيسية؛ المهلة تنبض لكن **لا يُقال للعميل ماذا يحدث إن لم يردّ أحد** (التوسيع موجود كإجراء لكنه لا يُقترح تلقائياً).
- نجاح الرحلة = عرضٌ خلال دقائق. القياس موجود في `analytics_events`.

## J2 — عميل: اعتماد أمر عمل (أهم لحظة قانونية)
- البداية: SMS/إشعار → شاشة الاعتماد (اللقطة الموقّعة) → نفاذ أو OTP → «تم».
- **الاحتكاك**: الشاشة تعرض اللقطة كاملة (صحيح قانونياً) لكن **الترتيب البصري يساوي بين البنود والإجمالي والشروط**؛ الإجمالي يجب أن يكون أول ما يُقرأ، ثم «ماذا يعني توقيعي» في جملة واحدة، ثم البنود.
- الشرط: لا اختصار يُضعف الفهم القانوني — التصميم يعيد الترتيب لا يحذف.

## J3 — عميل: الدفع والاستلام
- أمر مكتمل → «ادفع» (مدى/Apple Pay عبر PSP) → «المبلغ محفوظ حتى تستلم» → «أكّد الاستلام» → تحرير.
- **الاحتكاك**: جملة «المبلغ محفوظ» ممتازة، لكن حالة «محفوظ» و«مُحرَّر» تظهر بشارتين متشابهتين؛ الفرق بينهما هو كل القصة.

## J4 — ورشة: من الطلب إلى التسليم
- لافتة «طلب إصلاح وصلك» → شوف الطلب → قدّم عرضك → (قبول) → استلام → فحص ٨ زوايا → طلب اعتماد → تنفيذ → QC → جاهز → فاتورة → تسليم.
- **الاحتكاك**: زرّ رئيسي واحد لكل حالة (ممتاز)؛ لكن «المزيد» يخبّئ إضافة بند وصورة، وهما يوميّان للفنّي (قاعدة النقرتين تُخرق للفنّي لا للمالك).
- تبويبات الورشة ٤ + مساعد + «أمر جديد» في الرأس = ٦ مداخل في الشاشة الأولى.

## J5 — مورّد: من التنبيه إلى البيع
- لافتة → الطلب → قدّم عرضك (سعر، حالة، صور) → (قبول) → طلب للتجهيز → شحن → تسليم → المبلغ يُحرَّر.
- **الاحتكاك**: أُصلح اليوم غياب الزرّ لطلب العميل. يبقى: «مبيعاتي» تخلط ثلاثة أشياء (طلبات للتجهيز، حسابات آجلة، مخزون + QR) في قائمة واحدة طويلة (١٠ طلبات فوق المخزون).

## J6 — سائق: مهمة سطحة
- مهامي → قبول (بتأكيد الآن) → في الطريق → حمّلت → في الطريق للتسليم → تسليم وإثبات (صورة + رمز) → تم.
- **مُشي كاملاً ٢٣ سبتمبر**. الاحتكاك المتبقي: بعد التسليم يعود إلى شاشة فارغة بلا كلمة عن المبلغ («سيصلك ٩٠ ر.س بعد الفاتورة»).

## J7 — أسطول: قرار على إصلاح
- «بانتظار قرارك» → بطاقة الإصلاح → اعتماد/رفض → (التوقيع شخصي بعده).
- **الاحتكاك**: السياسة تُقرأ جيداً؛ **لا شاشة حاسوب** لمديرةٍ عندها ٤٠٠ سيارة — الكشوف والاستيراد على الجوال فقط.

## J8 — مشرف: KYB / نزاع / استرداد
- صفّ → ملف → قرار بسبب → تدقيق.
- **الاحتكاك**: اللوحة تعمل، لكن الهوية فيها غائبة تقريباً (PrimeNG Aura افتراضي مع بعض الرموز)؛ الجداول كثيفة بلا تسلسل بصري؛ «السبب» حوار عام لكل الإجراءات.

## الرحلات الحرجة لإعادة التصميم (بالترتيب)
1. **J1 + J4** (الحلقة نفسها) — الشاشة الأولى للعميل والورشة.
2. **J2** — لحظة التوقيع.
3. **J5** — «مبيعاتي» المورّد.
4. **J3** — وضوح حالة المال.
5. **J8** — اللوحة (هوية + كثافة).
